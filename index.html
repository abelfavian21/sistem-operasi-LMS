    MultithreadThread, bagian yang dibagi, model thread

    Thread adalah unit eksekusi terkecil di dalam satu proses. Satu proses bisa punya banyak thread yang berjalan bergantian atau bersamaan di beberapa core.

    Dibagi antar thread

    • Kode program
    • Data dan heap
    • File yang terbuka

    Milik tiap thread

    • Thread ID
    • Program counter
    • Register
    • Stack

    Manfaat multithreading

    • Responsif. Satu thread tetap jalan saat thread lain menunggu.
    • Berbagi resource. Memori dan file dipakai bersama tanpa IPC.
    • Hemat. Membuat dan berpindah thread lebih ringan daripada proses.
    • Skalabel. Memanfaatkan CPU multicore.

    Model hubungan thread

    Many-to-one
    Banyak user thread ke satu kernel thread. Satu thread blocking membuat seluruh proses terblokir.
    One-to-one
    Tiap user thread punya satu kernel thread. Bisa paralel, tetapi biaya lebih besar.
    Many-to-many
    Banyak user thread dipetakan ke sejumlah kernel thread. Fleksibel.

    Proses vs thread

    Proses punya ruang alamat sendiri, context switch berat, komunikasi lewat IPC. Thread berbagi ruang alamat, context switch ringan, komunikasi lewat memori bersama. Contoh: browser memuat halaman di satu thread dan mengunduh file di thread lain.

    Siklus prosesLima state dan transisinya

    Proses adalah program yang sedang dieksekusi. Keadaannya berubah selama berjalan.

    New
    Proses sedang dibuat.
    Ready
    Siap jalan, menunggu giliran CPU di ready queue.
    Running
    Instruksinya sedang dikerjakan CPU. Satu proses per core.
    Waiting
    Menunggu operasi I/O atau suatu event. Disebut juga Blocked.
    Terminated
    Selesai. Resource dilepas.

    Transisi

    • Admitted: New ke Ready.
    • Dispatch: Ready ke Running, dipilih scheduler.
    • Interrupt: Running ke Ready, quantum habis atau ada proses lebih penting.
    • I/O atau event wait: Running ke Waiting.
    • I/O atau event selesai: Waiting ke Ready, bukan langsung ke Running.
    • Exit: Running ke Terminated.

    PCB (Process Control Block) menyimpan state, program counter, register, info scheduling, dan info memori serta I/O tiap proses.

    Empat algoritma penjadwalanFCFS, SJF, Priority, Round Robin
    Turnaround = selesai - arrival
    Waiting = turnaround - burst
    Rata-rata = jumlah waiting / jumlah proses

    FCFS non-preemptive

    Aturan

    Siapa datang dulu, dilayani dulu (antrean FIFO).

    Plus

    Sederhana dan adil menurut urutan datang.

    Minus

    Convoy effect: proses pendek menunggu di belakang proses panjang.

    Trik

    Urutkan berdasarkan arrival time, jalankan sampai selesai.

    SJF non-preemptive

    Aturan

    Dari proses yang sudah tiba, pilih burst time terkecil.

    Plus

    Rata-rata waiting paling kecil.

    Minus

    Proses panjang bisa kelaparan (starvation). Burst time harus diketahui. Versi preemptive bernama SRTF.

    Trik

    Setiap proses selesai, cek siapa saja yang sudah tiba, ambil burst terkecil.

    Priority non-preemptive

    Aturan

    Pilih proses berprioritas tertinggi yang sudah tiba. Umumnya angka kecil berarti prioritas tinggi. Cek aturan di soal.

    Plus

    Proses penting didahulukan.

    Minus

    Prioritas rendah bisa tak pernah jalan. Solusinya aging, yaitu prioritas naik seiring lama menunggu.

    Trik

    Prioritas sama diselesaikan dengan FCFS.

    Round Robin preemptive

    Aturan

    Tiap proses dapat jatah CPU sebesar quantum (di soal q = 3). Jatah habis, proses ke belakang antrean.

    Plus

    Adil, cocok untuk time-sharing.

    Minus

    Quantum terlalu besar jadi mirip FCFS. Terlalu kecil membuat context switch terlalu sering.

    Trik

    Proses yang tiba tepat saat quantum habis masuk antrean lebih dulu daripada proses yang baru dihentikan.

    Fungsi komputer dan arsitekturKomponen, tiga bus, cara kerja instruksi
    Input device
    Memasukkan data dan perintah. Contoh: keyboard, mouse, scanner.
    I/O ports
    Gerbang penghubung CPU dengan perangkat luar. Mengatur lalu lintas data masuk dan keluar.
    CPU
    Pusat pengolah. CU mengambil dan menerjemahkan instruksi lalu mengatur sinyal kontrol. ALU mengerjakan operasi hitung dan logika. Register menyimpan data sementara di dalam CPU.
    Memori
    RAM menyimpan program dan data yang sedang berjalan, isinya hilang saat listrik mati. ROM menyimpan program tetap seperti bootstrap, isinya bertahan.
    Output device
    Menampilkan hasil. Contoh: monitor, printer, speaker.
    Data bus
    Jalur dua arah pembawa data.
    Address bus
    Jalur satu arah dari CPU, membawa alamat lokasi memori atau I/O.
    Control bus
    Pembawa sinyal kendali: read, write, interrupt, clock.

    Cara kerja satu instruksi

    1. Data atau program masuk lewat input device dan I/O port, lalu disimpan di memori.
    2. Fetch: CPU mengirim alamat lewat address bus dan sinyal read lewat control bus. Instruksi datang lewat data bus.
    3. Decode: CU menerjemahkan instruksi.
    4. Execute: ALU mengerjakan operasi.
    5. Hasil disimpan ke memori atau dikirim ke output device lewat I/O port.

    Soal 1 · 20 poin

    Berdasarkan diagram komponen sistem komputer, jelaskan fungsi tiap komponen dan cara kerjanya.

    • Input device memasukkan data. I/O port menyalurkannya ke CPU dan memori.

    • Output device menampilkan hasil.
    • Data bus membawa data (dua arah), address bus membawa alamat (dari CPU), control bus membawa sinyal kendali.
